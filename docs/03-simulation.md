# 03 — Модель симуляции

Все цифры ниже — стартовые ориентиры баланса, выносятся в единый конфиг (`balance.ts`) и тюнятся плейтестами.

## Воронка (полностью видна игроку)

```
 Каналы трафика                Продукт                    Деньги
┌──────────────┐   визиты   ┌───────────┐  подписки   ┌──────────┐
│ SEO          │──────────▶ │  Лендинг  │───────────▶ │   MRR    │
│ Соцсеть (X)  │            │ conv_lp % │             │ = paid × │
│ Форумы       │            └───────────┘             │   ARPU   │
│ Реклама ($)  │                  │                   └──────────┘
│ Лонч-всплеск │            регистрации                     ▲
│ Аудитория 👥 │                  │                          │
└──────────────┘            ┌───────────┐    − churn % ──────┘
                            │  Продукт  │
                            │ conv_pay %│
                            └───────────┘
```

### Тик дня (упрощённый псевдокод)

```
visits      = Σ по каналам (база канала × вложенные усилия × decay) + ads($/CAC) + launch_spike
signups     = visits × conv_lp                // conv_lp: качество лендинга × PMF
new_paid    = signups × conv_pay              // conv_pay: качество продукта × PMF × цена-фактор
churned     = paid × churn_rate               // churn: качество, баги, саппорт
paid        = paid + new_paid − churned
MRR         = paid × ARPU
money       += MRR/30 − burn_rate/30 − траты дня
audience    += посты × виральность + доля signups
```

## Ключевые скрытые/открытые параметры

| Параметр | Виден? | Что определяет |
|---|---|---|
| **PMF (0–1)** | скрыт, проявляется в конверсиях | Насколько идея попала в спрос. База задаётся нишей, повышается валидацией/донор-ресёрчем/общением с юзерами |
| Ниша: спрос, конкуренция, ARPU-потолок | скрыты до валидации | Валидация открывает истинные значения (до неё игрок видит только «легенду» идеи) |
| Качество лендинга (0–1) | видно | conv_lp: 0.5%–8% |
| Качество продукта (0–1) | видно | conv_pay: 1%–10%, churn: 2%–20%/мес |
| Баги (счётчик) | видно | +churn, −мотивация при инцидентах |
| Эффективность канала | видна после вложений | У каждого канала: cost-кривая, задержка отдачи (SEO — медленно/дёшево, реклама — мгновенно/дорого, соцсеть — зависит от аудитории) |

## Экономика

| Статья | Значение (старт) |
|---|---|
| Burn rate «жизнь» | $1,500/мес, списывается подневно |
| Инфраструктура | $20/мес после деплоя, растёт ступенями с числом юзеров ($20 → $100 → $500 → $2k…) |
| NPC-помощники | $500–$5,000/мес каждый |
| Реклама | CAC $1–$50 за визит→signup в зависимости от канала/ниши/лендинга |
| ARPU | $10–$100, задаётся ценой игрока, ограничен потолком ниши |

Давление времени создаёт burn rate: без дохода стартовых денег хватает на ~2.5–4 месяца игрового времени.

## Ниши (генерация идей на старте рана)

На старте рана игроку показываются 3 случайные идеи из пула (~15–20 ниш-шаблонов): «AI-тулза для скриншотов», «трекер привычек для котов», «SaaS для выгула драконов»… У каждой скрытые параметры (спрос/конкуренция/ARPU-потолок/виральность) + короткая ироничная легенда. Часть идей — заведомо мёртвые (спрос ≈ 0): валидация существует, чтобы это выяснять до, а не после.

## Рандом

- Все броски — через seeded RNG (seed рана показывается игроку; можно шарить «daily seed» в будущем)
- Дисперсия дневных метрик: ±30% к ожиданиям — «жизнь шумная»
- События дня — см. 04: вероятности по категориям, взвешенные стадией рана

## Победа/поражение — сводка условий

```
ПОБЕДА:     MRR ≥ $10,000
ПОРАЖЕНИЕ:  money ≤ 0   ИЛИ   motivation ≤ 0
```

Экран конца рана: график MRR/денег за весь ран, причина смерти, ключевые решения, счёт (дней до победы / достигнутый MRR), кнопка «Новый ран».
